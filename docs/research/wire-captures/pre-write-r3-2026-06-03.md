# CFG.PRE has no routed-action setter — `r=-3` (2026-06-03)

**Severity:** clarifying — closes a long-standing *extrapolated* claim with direct evidence.

## Question

EdgeMaster (`s6p2[2]`) and Mowing Efficiency (`s6p2[1]`) were carried in code
(`switch_map.py`) and docs as "no working device-write surface identified" — but
that was **never tested on their own surface**. The cloud-cache-only proof
(`settings-surface-cloud-only-2026-05-09.md`) was on a SETTINGS chunked-batch
field (`obstacleAvoidanceAi`); mowing height's "writable" entity rides that same
cloud-cache-only SETTINGS batch, so it is not a working example to generalise
from. Mowing Efficiency's real home is `CFG.PRE[1]`, whose write path
(`cfg_action.set_pre` → routed-action `{m:'s', t:'PRE', d:{value:…}}`) is the
**same transport tier proven to drive the device for 9 simple CFG keys**
(CLS/FDP/STUN/AOP/PROT/VOL/ATA/MSG_ALERT/VOICE — `cfg-write-regression-2026-05-09.md`).
`PRE` was never in that 16-key probe. This run tests it directly.

## Method

`tools/probe_pre_write.py --probe` against the live g2408 (fw 4.3.6_0550),
mower awake (relay confirmed alive). The probe builds the wire envelope by hand
(bypassing `set_pre`'s `len<10` guard) so it can send the **correct g2408
2-element shape** `[zone_id, mode]`, and reads `out[0].r`.

## Result (verbatim)

```
--- relay control: routed_action op=9 (findBot, harmless beep) ---
  ← result: {"aiid": 50, "code": 0, "out": [{"m": "r", "q": 71, "r": 0}], "siid": 2}
  relay ALIVE — a PRE r=-3/r=0 below is a genuine device verdict.

  PRE (before): [0, 0]  (zone_id=0, mode=0=Standard)  CFG.VER=816

Will flip mode 0 → 1 (2-element shape [0, 1]).

→ shape='wrapped'  payload=[0, 1]
  wire: action(siid=2, aiid=50, [{"m":"s","t":"PRE","d":{"value":[0,1]}}])
  ← reply: {"aiid": 50, "code": 0, "out": [{"m": "r", "q": 73, "r": -3}], "siid": 2}
  out[0].r=-3
```

## Conclusion

- **`CFG.PRE` has no setter registered at the `s2.50` routed-action address on
  g2408 firmware 4.3.6_0550.** The control (findBot op=9, identical transport)
  returned `r=0` immediately before, so the `r=-3` is a genuine firmware verdict,
  not a sleeping-relay `80001`.
- Per the 2026-05-09 r-code disambiguation, **`r=-3` is target-level** ("no setter
  for this `t=KEY`"), independent of payload shape — so the `bare` and `named`
  variants would return `r=-3` identically. The disproof does not depend on shape.
- **Mowing Efficiency (PRE[1]) is NOT device-writable via the routed-action CFG
  surface.** Same class as the int-list CFG keys (DND/LOW/WRP/BAT/LIT/REC/LANG).
- **EdgeMaster (s6p2[2])** has no PRE slot on g2408 (PRE is 2-element) *and* PRE
  has no setter anyway — so it is covered by the same finding.
- The earlier "no write surface identified" was directionally correct but was
  **extrapolation**; this is the first direct evidence for the PRE/efficiency surface.

## Integration implication (shallow-success bug)

`cloud_client/_fetchers.py:set_pre` returns `True` whenever the reply is not
`None`. An `r=-3` reply IS a (non-None) dict, so `set_pre` currently reports
**false success** for the efficiency select — same shallow-success bug class as
the pre-v1.0.2a9 `set_cfg`. The honest fix is to parse `out[0].r` and treat any
non-zero `r` as failure (mirroring the `set_cfg` fix), or to make the efficiency
select read-only like `switch_map.DreameA2MapEdgemasterSwitch`.
